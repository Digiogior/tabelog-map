# Tabelog-map mobile UX mockup prompts

Generated with the built-in image generation tool. These are proposed UI concepts; maps, restaurant names, ratings, and browser permission appearance are illustrative.

## 01-choose-an-area

Use case: ui-mockup.
Create a high-fidelity mobile website UX design board for tabelog-map, a Japanese restaurant discovery map. One image, landscape composition, exactly TWO large front-facing mobile UI screens side by side, no perspective, no hands, no device photography. Each screen has a subtle thin rounded phone frame and about 390x844 proportions. Generous outer canvas margins, neutral warm light gray background, concise numbered state captions outside below phones. The screens must be large enough for all text to be legible. Cohesive professional product UI: off-white #FAFAF8 surfaces, white cards, charcoal text, coral red #E74C3C primary buttons and map pins, blue #007CBF only for current location, soft gray dividers, 16px equivalent body text, clean modern sans-serif, restrained rounded corners, 48px minimum touch buttons. Header wordmark exactly "tabelog-map" with a small coral map-pin symbol. Mobile browser presentation with quiet bottom Safari-style address strip displaying "tabelogmap.com", simple 9:41 status bar. This is a responsive WEBSITE, not a native app: no invented bottom app tab bar. Crisp realistic polished UI, coherent spacing and icon style across screens, no decorative illustrations, no marketing slogans, no arrows between screens, no extra screens. Maps are illustrative quiet street maps around Shinjuku with sparse legible neighborhood labels. Restaurant names, ratings and result counts are fictional mock data. Render only the requested UI labels, not these instructions. Settings must never gate manual restaurant search.
